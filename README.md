> **学习参考与账号风险声明**
>
> 本项目仅供学习、研究与技术参考，不代表 OpenAI、Google 或其他服务商的官方产品或授权。使用前请阅读并遵守相关服务条款及适用规则，仅处理自己拥有或明确获授权的账号与邮箱。
>
> **自动化注册、登录、获取授权及通过第三方后端导入会话，可能触发风控、额外验证、账号限制、暂停或永久封禁。固定等待、逐字输入和无痕模式不能消除封号风险，本项目不保证注册成功、账号安全或持续可用。** 请勿使用重要账号进行测试，并自行评估账号、订阅及数据损失风险。Cookie、Token、密码和 Gmail 授权均属于敏感信息，妥善保管，详情见 [本地数据与安全说明](SECURITY.md)。

Windows 浏览器辅助工具，配合 [basketikun/chatgpt2api](https://github.com/basketikun/chatgpt2api) 使用：串行处理自有域名邮箱，通过 Gmail 只读 API 获取验证码，填写资料，在官方跳转页面稳定后提取 OAuth 回调或读取浏览器 Session JSON，交给后端导入。

**兼容基线：chatgpt2api v1.8.0，提交 [`dc105e51bd486bd75c8ef4f74be4bc4724bdfc33`](https://github.com/basketikun/chatgpt2api/tree/dc105e51bd486bd75c8ef4f74be4bc4724bdfc33)，OAuth 模式加本仓库附带的 Platform OAuth 回调补丁；Session JSON 模式使用该版本原有接口。** 未验证的上游新版本或直接使用 `latest` 镜像不保证兼容，详见 [版本说明](docs/COMPATIBILITY.md)。

本项目源码仓库：[jasonlat-dot/chatgpt-auto-register](https://github.com/jasonlat-dot/chatgpt-auto-register)。

## 功能

- 并发固定为 1，每个账号结束并关闭页面后再处理下一个。
- 自动模式遇到手机 / 人机验证、未知表单、取码失败或超时直接跳过，不弹出人工处理选择。
- 独立的 Session JSON 自动登录导入：核对邮箱、读取当前浏览器的 accessToken，确认后端账号仍在池中后才记为成功。
- 普通和无痕浏览器可切换；普通模式按邮箱保存独立资料，无痕模式结束后销毁会话。
- 本地生成姓名、18–50 岁范围内的有效生日和随机密码，重试复用同一资料。
- 生日填写支持原生日期、可识别文本日期和年 / 月 / 日分段控件；覆盖默认当天值，并在提交前检查可见值及可识别的隐藏日期。无法确认时跳过，避免提交当天日期。
- 成功导入后从 `accounts.txt` 移到 `accounts-completed.txt`；跳过和失败的保留。
- 输入数量和域名，按后续填表的“姓名小写连写 + 出生日期 YYYYMMDD”生成待处理地址，检查待处理、已完成及本地历史数据避免重复。
- 结束时汇总结果，保存 `.local/last-run-summary.json`；兑换结果未知的账号不自动重试。

浏览器页面会变化。本项目有模拟邮件、合成页面和真实浏览器驱动测试，不能把模拟通过等同于真实服务端注册成功。建议先用一个自有邮箱验证实际页面和转发格式。程序不解决手机验证或人机验证，也不调用 GPT 来理解页面。

| 后端 | WSL / 其他主机运行上述版本的 chatgpt2api；OAuth 模式另需回调补丁 |

## 快速开始

在 Windows 的固定用户目录中操作，不需要把自动化程序放到 WSL。

```powershell
git clone https://github.com/jasonlat-dot/chatgpt-auto-register.git
cd chatgpt-auto-register
Copy-Item config.example.json config.json
Copy-Item accounts.example.txt accounts.txt
```

编辑本地 `config.json`，确认 `api_base_url` 指向后端。默认示例为 `http://127.0.0.1:3000`，`proxy` 默认留空；需要代理可填 `http://127.0.0.1:7890`，按自己的端口调整。此配置与 WSL 后端的同名文件是两份独立配置。

按照 [域名邮箱教程](docs/DOMAIN-EMAIL.md) 准备收信及转发，再按照 [Gmail API 教程](GMAIL-SETUP.md) 启用 API、创建个人桌面应用凭据并保存为 `credentials.json`。

双击 `start.cmd`，输入数字并按回车：

| 选项 | 用途 |
| --- | --- |
| 1 | 连接 Gmail / 首次只读授权 |
| 2 | 预览本地队列、姓名、年龄和状态，不注册 |
| 3 | OAuth 全自动运行，需要人工处理则跳过，最后汇总 |
| 4 | 主动手动接码；验证码直接填在浏览器页面 |
| 5 | 清理失效队列锁；进程仍在运行时不会删除 |
| 6 | 输入数量与自有域名，追加不重复邮箱到队列 |
| 7 | 选择普通 / 无痕浏览器，并保存选择 |
| 8 | 查看异常账号与原因，单个或批量重新排队 |
| 9 | Session JSON 自动登录并导入，使用已有账号 |
| 0 | 退出 |

这些是独立功能，不是每次都按 1–9 顺序执行。第一次可先用 **1** 授权，再用 **6** 生成一个地址、**2** 预览、**3** 运行；以后授权有效时可直接用 3。每项结束后回到同一个菜单。程序优先读取本地配置中的 **chatgpt2api 管理员密钥**；缺失或认证不通过时才提示输入。它不是 OpenAI API key 或 Gmail 密码。

`accounts.txt` 每行一个真实的自有邮箱；空行和以 `#` 开头的注释会忽略。示例中的 `.example` 地址需要替换。菜单 6 只生成地址，不能自动购买域名或建立真实邮箱，域名必须已有收信 / catch-all 配置。

自动化打开的是脚本专用浏览器，**不需要在其中打开 chatgpt2api 网页，也不需要安装回调扩展**。程序直接调用后端 API。

## 保存后端管理员密钥

本地 `config.json` 新增字段：

```json
"chatgpt2api_admin_key": ""
```

可以自己填写，也可留空，在选择 3 / 4 / 9 时通过隐藏输入框提供。程序先读取此字段，未填写时兼容 `CHATGPT2API_ADMIN_KEY` 环境变量；仍缺失或认证失败时要求重新输入。**新输入仅在管理员认证成功后保存到本机 `config.json`**，保留其他配置项，错误输入不覆盖旧配置。空输入取消并返回菜单。

认证使用后端的 `/auth/login` 并确认 `admin` 角色，不会把 Gmail 授权失败当成后端密钥失败。网络超时或服务端异常会单独报错，不会反复询问密钥。全部账号都是历史未重试状态时，仍先显示队列说明，不索要密钥、不连接 Gmail。

保存的密钥是本地明文配置，应保留在自己的电脑上；`config.json` 已被 Git 忽略，公开仓库只提供密钥为空的 `config.example.json`。程序不在终端、日志或运行摘要中输出密钥。

## OAuth 固定等待与关闭顺序

菜单 3 / 4 的 OAuth 流程在观察到页面和可见表单稳定后，固定等待 **2 秒**再执行该次页面操作；验证码提交同样等待。等待期间若发生导航或表单结构变化，本轮不填表，下次重新等待。此等待按页面操作执行，不为同一表单中的每个字段分别计时。

验证码或资料表单提交后，未知/转圈过渡页最多等待 **60 秒**，不再按普通未知页的 3 秒规则提前跳过。明确的手机/人机验证仍直接跳过；全局授权会话到期限制仍生效。验证码按钮暂未启用时继续等待，只有点击到可用的提交按钮才标记已提交。

OAuth（3 / 4）与 Session JSON（9）都在页面操作前固定等待 **2 秒**。邮箱、密码、姓名、年龄、验证码及文本日期按每字 **500 毫秒**逐字输入，字段之间等待 **1 秒**，点击“继续”前再等待 **1 秒**。六格验证码视为一个字段；日期选择器和下拉框按控件格式设置，填完同样等待。输入时遇到用户手工修改会停止自动提交，不覆盖手工内容。输入操作的调试等待上限为 5 分钟，避免长邮箱和密码在逐字输入时触发原来的短超时；原有整体授权有效期仍适用。

OAuth 允许官方页面正常跳转，不阻断或替换官方回调响应。程序仅在内存保留本次主文档回调地址；跳转后的页面完成加载、无可识别的加载指示并稳定约 **1 秒**后，才校验并提取 code/state，再等待 **1 秒**向后端提交。若官方用 HTTP 重定向移除了地址栏中的 code，仍使用本次观察到的回调地址；不重复打开该地址。

**正常官方跳转可能已经兑换 code；等页面稳定后再次交给后端，不保证仍可兑换。** 导入失败会提示这种可能，结果待核对的账号不会自动重复提交。后端确认导入后保留官方页面，在页面和终端显示 **3、2、1 秒**关闭倒计时，然后关闭浏览器并开始下一账号；不跳转本地完成页。等待期间按 Ctrl+C 会停止。Session JSON 菜单 9 不增加导入后的关闭倒计时。

## 关闭前的页面加载检查

OAuth（3 / 4）和 Session JSON（9）的成功、跳过、失败及停止清理路径，都先检查当前主页面：等待主文档完成加载，没有识别到可见加载指示，并保持同一文档稳定约 1 秒，才关闭页面和浏览器。填表与 Session 读取期间也检查主页面导航；密码提交后正在跳转时，不会读旧页或把页面当成未知表单。

关闭检查额外等待约 30 秒。如果始终加载不完或无法确认，**保留当前窗口并停止整个队列，不启动下一个账号**。控制台会明确提示；请查看保留的页面后手动关闭，再选择后续操作。已确认导入的结果仍记为已导入，跳过/失败/结果未知保持原有重试保护，不因保留窗口而变成成功。

OAuth 回调请求不再被拦截，浏览器正常访问官方下一页。只有官方跳转后的页面加载稳定，才释放本次授权信息供后端导入；最长等待约 60 秒。导入成功后的结果提示和倒计时附加在原页面上，不替换官方文档或地址。未确认导入、跳过或错误时不显示成功提示。

## Session JSON 自动登录导入

选择菜单 **9**。程序逐个处理 `accounts.txt` 中的待处理邮箱：

1. 使用菜单 7 选定的普通 / 无痕模式打开脚本浏览器，访问 ChatGPT 登录入口。
2. 优先复用当前账号的已有会话；需要登录时识别 ChatGPT 自己显示的邮箱页，或跳转后的认证页，填写邮箱和已有本机密码，通过 Gmail 自动获取验证码。
3. 在同一个浏览器上下文请求 `https://chatgpt.com/api/auth/session`，核对 `user.email` 与当前队列邮箱，检查可读取的过期时间。邮箱不匹配、无法核对或已过期时跳过。
4. 提取 `accessToken`，与网页“导入 Session JSON”一致，调用后端 `POST /api/accounts`，不经过 OAuth start/finish。
5. 后端响应确认账号仍在池中后归档；提交后超时、响应异常或账号不在最终列表时标记“结果待核对”，不盲目重复提交。

已有普通模式登录状态时可以不依赖 Gmail；需要验证码时仍需配置 Gmail。无痕模式每个账号都是全新会话。此入口用于**登录已有账号**，不会主动点击注册链接；首次注册继续使用原有流程。脚本使用本机已有密码，若账号密码不同或页面无法适配，会跳过并报告。

Session 通常只提供 accessToken，**不等同于 OAuth 的 refresh_token / id_token 凭据**，本工具不会通过此模式获得 OAuth 自动续期能力。Token 过期后需重新登录获取；后端能否导出完整 Codex 凭据也取决于是否已有其他凭据。

完整 Session 和 accessToken 只在内存中传递给你配置的后端，不写入本地文件、终端或摘要。普通模式的浏览器 Cookie 仍保存在原有独立资料目录。此模式无需浏览器插件，也无需为它重新打后端补丁或构建镜像。

如果账号导入后消失，请检查后端 **设置 → 自动移除异常账号** 以及日志；程序不会替你修改后端清理设置。

## 自动模式与结果

选项 3 和 9 遇到需要人工处理的步骤会关闭当前账号页面并继续下一账号。普通未知页面有约 3 秒渲染缓冲，连续无进展约 45 秒跳过；刚提交验证码/表单后的过渡阶段最多等待 60 秒。邮件等待默认 60 秒，可用 `auto_code_wait_seconds` 调整。

自动模式不会启动首次 Google 授权；Gmail 未配置或已失效会记录跳过。此时先选择 1 重新连接。旧配置中的 `manual_codes` 不再控制运行模式；需要手动时明确选择 4。

| 文件 | 内容 |
| --- | --- |
| `accounts.txt` | 待处理邮箱；跳过 / 失败的仍在这里 |
| `accounts-completed.txt` | 已确认成功导入的邮箱 |
| `.local/status.json` | 账号状态与异常原因；避免重复兑换 |
| `.local/last-run-summary.json` | 最近一次运行的结果、数量及 `import_mode`（oauth / session_json） |
| `.local/account-credentials.json` | 本机生成的姓名、生日和明文密码 |
| `.local/gmail-token.json` | Gmail 授权 token |
| `.local/browser-settings.json` | 普通 / 无痕模式选择 |
| `.local/browser-profiles/` | 脚本的独立浏览器资料 |

菜单 **6** 先生成并保存一份姓名、18–50 岁范围内的有效生日和密码，再将对应邮箱追加到队列。例如姓名 `Alex Miller`、生日 `1996-05-17`、域名 `example.com`，得到 `alexmiller19960517@example.com`。姓名去掉空格和标点并转为小写；邮箱前缀不再添加 `user` 或随机字符串。姓名加生日发生碰撞时换一份资料重试，不添加随机后缀。保存资料失败时不追加邮箱。

菜单 **2 / 3 / 4 / 9** 复用这份资料，填写的姓名和生日与新生成邮箱对应；年龄按同一生日计算。已存在的邮箱、队列状态及资料不会因升级改名或重置。姓名加生日会直接暴露在邮箱地址中，请自行评估隐私影响。

成功和已入库但刷新有警告的邮箱都会归档。跳过、失败、进行中和兑换结果未知的历史记录不会自动重试；文件仍在并不代表下一次会盲目重新执行。核对后端账号池后，可显式重新排队：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\start.ps1 Retry -Email "你要重试的邮箱@自己的域名"
```

也可以直接使用菜单 **8**：列表显示邮箱、中文状态、原因与下一步；输入序号重新排队单个账号，输入 **A** 批量重新排队“已停止 / 失败 / 跳过”。结果待核对和上次处理中断的账号不会加入批量重试，须先检查后端账号池，确认未入库后在单个重试时明确确认。已成功导入或位于已完成文件中的账号不能重新排队。

重新排队只改状态，不立即开始注册；保留原资料，并记录上次状态和原因。如果全部账号都是历史未重试状态，选择 3 / 4 / 9 会先显示原因及菜单 8 的处理方式，不再索要管理员密钥或连接 Gmail。菜单 5 只清理运行锁，不能重置账号状态。

命令行重试 `unknown_after_submit` 或 `in_progress` 时也必须先核对账号池。确认未入库后，上面的 PowerShell 命令额外加 `-ConfirmedNotImported`；直接使用 `node runner.mjs --retry` 时额外加 `--confirm-not-imported`。其他停止或跳过状态可沿用上面的命令。

然后重新选择 3 / 4（OAuth）或 9（Session JSON）。OAuth 会生成新的授权会话，不重复提交旧 code；Session 模式重新读取当前登录会话。两者复用本机资料。`Ctrl+C` 请求停止；整体配置错误、写盘失败或浏览器无法关闭时会停止队列并输出已完成部分的摘要。

普通浏览器按邮箱隔离，不复用你平时的浏览器资料。关闭时等待写盘，可能需要几秒；无痕模式不删除之前普通模式的资料，也不删除 Gmail 授权或队列状态。

程序现在明确使用 **Google Chrome**，没有安装时提示安装，不自动切换到 Edge。菜单 7 选择无痕后，使用 `--incognito` 启动并直接操作 Chrome 原生无痕窗口；普通模式不加此参数。启动日志显示浏览器和实际模式。旧版优先使用 Edge，且只创建隔离的调试上下文，窗口外观可能与菜单的“无痕”描述不一致。

Chrome 的脚本专用资料保存在原邮箱资料目录下的 `chrome/` 子目录，以免直接打开或覆盖旧版 Edge 资料。旧资料保留；升级后普通模式首次使用 Chrome 可能需要重新登录。无痕模式的 Cookie 和站点存储不跨会话保留。

## 更新与本地数据

提交和公开仓库只包含源码、示例配置、教程、测试以及固定版本补丁。[SECURITY.md](SECURITY.md) 说明忽略规则与本地数据范围。不要提交 `config.json`、`credentials.json`、真实邮箱列表、`.local`、日志或原始截图。

以后更新先退出队列，再在此目录运行 `git pull --ff-only`。本地配置和运行数据被 Git 忽略，不随正常源码更新覆盖；备份时也应把这些私有数据单独保存，不要为了备份加入 Git。

## 常见问题

- **生日仍是当天**：确认正在运行新版 `browser.mjs` 和 `birthday.mjs`。不支持的日期结构会跳过；提供脱敏控件 HTML 或截图供适配，勿提交验证码 / Cookie。
- **Gmail 403 access_denied**：检查当前 Google 项目的测试用户名单；添加的是接收邮件并实际登录授权的 Gmail。
- **此应用未经 Google 验证**：仅在确认是自己创建的客户端时，按 Google 页面提示继续自己的测试授权。详细步骤见 Gmail 教程。
- **连接后端失败**：确认服务运行、端口可达、`api_base_url` 正确。Windows 程序的代理与 WSL 后端的出站代理分别配置。
- **历史记录未重试**：用菜单 8 查看状态和原因；修复原因后重新排队，再运行 3 / 4 / 9。已停止、失败和自动跳过都采用这个流程，结果待核对的先检查账号池。
- **队列锁未释放**：确认旧程序退出后用菜单 5；不要删除整个 `.local`。
- **填完资料后一直转圈**：现在不拦截官方跳转。尚未出现“已获取 OAuth 完成信息”时，不代表已可提交；程序要先观察到官方回调，再等目标页面加载稳定。一直无进展时按超时策略给出原因；无法确认页面加载完成时保留窗口。只有“后端已确认导入”和结果摘要才表示本次确认入库。
- **code 已使用 / 兑换结果未知**：先检查账号池，再显式重试；不要再次提交旧回调。
